# Cudy SSH Enabler

**English** | [Русский](README.ru.md)

Generated by Claude AI based on this research: https://4pda.to/forum/index.php?showtopic=1115130&view=findpost&p=143819120

Tools to **decrypt, patch, and re-encrypt the configuration-backup (`.bin`) files** produced
by Cudy routers (WR3000 / TR3000 family and relatives), so that **root SSH (and telnet)
access is enabled** on the device after you restore the patched backup.

It ships in two front-ends that share a single core:

- **`cli.php`** — a command-line tool.
- **`index.php`** — a small web UI (upload a backup in the browser, get a patched one back).
- **`common.php`** — all the shared logic (crypto, pure-PHP tar, the embedded overlay, and the
  `.env` / `models.txt` loaders). Both front-ends `require` it.

Everything is written in **plain PHP** — no Composer packages, no external libraries. Tar
handling is implemented from scratch; only PHP's built-in `openssl` and `zlib` extensions are
used. The `etc/` + `overlay/` tree that enables SSH is embedded directly in `common.php`, so
there are no extra data files to ship.

> ⚠️ **Use only on hardware you own.** This modifies a backup of *your own* router to regain
> administrative access to it. Enabling SSH/telnet and setting a root password weakens the
> device's security — do it deliberately, use a strong password, and don't expose the router's
> management services to the internet.

## What it actually does

A Cudy settings backup is **not** a plain archive. The `.bin` file is:

```
AES-128-CBC( gzip( tar( /etc config files … ) ) )  + a 48-byte encrypted header
```

- **Encryption:** AES-128-CBC, zero IV, custom chunked framing with an end-of-data marker
  (reverse-engineered from the firmware's `/usr/bin/crypt`).
- **Key:** `MD5( "<MODEL>@<KEY_BASE>" )` — i.e. the key depends on the **router model**. The
  shared secret (`KEY_BASE`) is baked into the firmware; the model prefix is what changes
  between devices.

> 🔑 **You must provide `KEY_BASE` yourself** via a `.env` file in the project directory, next to
> `common.php`, containing one line:
>
> ```
> KEY_BASE=the-real-firmware-secret
> ```
>
> Copy `.env.example` to `.env` and fill it in. Both front-ends read the same `.env`. Without a
> valid key the tool falls back to the placeholder `xxx` and nothing will decrypt. `.env` is
> git-ignored so the secret is never committed.
- **Header:** a 48-byte block carrying a magic value (`0xA1ECD5BD`), a timestamp, a random
  value, and the firmware build string.

The tool:

1. **Auto-detects the model** by trying each known model key in turn until the decrypted
   header magic matches — so you don't have to know which model the backup came from.
2. **Decrypts** the payload.
3. **Un-gzips and un-tars** it (pure PHP).
4. **Merges in a small embedded `etc/` + `overlay/` tree** that enables SSH/telnet on boot
   (see below), replacing same-named entries and leaving the rest of your config untouched.
5. **Sets the root password** you choose (the `NEWPASS` variable in `etc/rc.local`).
6. **Re-tars, re-gzips, and re-encrypts** with the same model key, preserving the original
   build string in the header.

The result is a drop-in replacement backup you restore through the router's normal
*"Restore configuration"* page.

### What gets injected (`etc/rc.local`)

On the next boot the patched `rc.local`:

- removes the `uci-defaults` script that would otherwise reset the root password,
- comments out the `bdinfo dbg` guard in the dropbear/telnet init scripts,
- creates the `/etc/rom_dbg` debug flag,
- enables `ttylogin`,
- **sets the root password** to your chosen value,
- enables and starts **dropbear (SSH)** and **telnet**.

The exact script is embedded in `common.php` (look for `embedded_entries()`). The `NEWPASS='...'`
line is rewritten to your password every run — the tool always asks, even if the backup was
patched before.

## Supported models

The models are listed in **`models.txt`** (one per line) and tried from top to bottom; the first
one whose header magic matches wins:

```
AP1300, AP3000, C200P, LT300, LT400, LT500, LT700, M1200, M1300, M1800,
M3000, R700, RE1200, RE1800, RE3000, TR30, TR3000-256MB, WBR3000UAX,
WR1300, WR2100, WR3000, WR3000E, WR3000H, WR3000P, WR3000S,
WR3000U-256MB, X6
```

Both front-ends read the same `models.txt` (next to `common.php`). If your backup is from another
model that uses the same scheme, just add its exact model string on its own line. Detection is
safe: a wrong key simply fails the magic check and the next model is tried.

## Requirements

- **PHP 8.0+** (CLI for the command-line tool, or PHP-FPM/`php -S` for the web UI)
- PHP extensions **`openssl`** and **`zlib`** (both enabled in standard builds)

Check with:

```bash
php -v
php -m | grep -E 'openssl|zlib'
```

## Command-line usage (`cli.php`)

```bash
php cli.php <input.bin> [output.bin] [--pass=<sshpass>] [--model=<model>]
```

- `<input.bin>` — the encrypted backup exported from the router.
- `[output.bin]` — optional; defaults to `<input>-patched.bin`.
- `--pass=<sshpass>` — the root/SSH password to set. If omitted, you're prompted for it.
- `--model=<model>` — skip auto-detection and force a specific model key.

**Example:**

```bash
php cli.php backup-WR3000U-256MB-2026-07-26.bin --pass='MyStrongPass!'
```

```
[+] Model detected: WR3000U-256MB
    build=2.4.29-20260427-104733  date=2026-07-26 10:02:04  payload=35426 bytes
[+] SSH enabled
[+] Set NEWPASS in etc/rc.local

[✓] Done. Wrote backup-WR3000U-256MB-2026-07-26-patched.bin (36910 bytes), model=WR3000U-256MB
```

## Web usage (`index.php`)

A browser UI served by `index.php` (which uses `common.php`).

### Files

| File | Purpose |
|------|---------|
| `index.php` | Web front-end: a JSON API (`detect` / `patch`) that serves `page.html`. |
| `common.php` | Shared crypto / tar / overlay / loader logic. |
| `page.html` | The HTML view. |
| `style.css` | Styles (terminal/console theme). |
| `script.js` | Front-end logic. |
| `models.txt` | The model list. |
| `.env` | Your `KEY_BASE` (create from `.env.example`). |

### Run locally

```bash
php -S 127.0.0.1:8080
# open http://127.0.0.1:8080/
```

### Deploy (nginx + php-fpm, or Apache)

Copy the project files into your web root, e.g.:

```bash
sudo cp common.php index.php page.html style.css script.js models.txt /var/www/html/
# then create /var/www/html/.env with your KEY_BASE
```

Make sure `index.php` is in your server's index list and that `.php` is handled by PHP-FPM.

### Flow

1. **Select / drop a `.bin`.** The browser uploads it and the server **auto-detects the model**;
   the detected model and build info are shown in the console-style log.
2. If detection succeeds, the **SSH password field and “run” button appear**.
3. Enter the password and press **run** — the backup is patched server-side and the
   re-packed `.bin` **downloads automatically**.

> Uploads are limited by PHP's `upload_max_filesize` / `post_max_size` (2 MB / 8 MB by default).
> Backups are tiny (tens of KB), so this is fine; raise the limits if you ever need to.

> 🔒 The web UI decrypts firmware and sets a root password using the key from `.env`. **Keep it on
> localhost or a trusted LAN — do not expose it to the public internet**, and add authentication
> if others can reach it.

## Restoring the patched backup to the router

1. Log in to the router's web admin.
2. Go to the configuration **Backup / Restore** page.
3. **Restore** using the patched `*-patched.bin` file. The router reboots.
4. After reboot, connect over SSH as `root` with the password you set:

   ```bash
   ssh root@192.168.10.1
   ```

   (Telnet on port 23 is also enabled as a fallback.)

If something goes wrong, you still have your **original, unmodified backup** — keep it.

## How detection works (for the curious)

```
for each MODEL in models.txt:
    key = MD5(MODEL + "@" + KEY_BASE)        # 16-byte AES-128 key
    header = AES-128-CBC-decrypt(first 48 bytes, key, IV=0)
    if little-endian uint32 at header[0] == 0xA1ECD5BD:
        → correct model found
```

Because a wrong key yields a wrong magic value, detection never produces a false positive.

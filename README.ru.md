# Cudy SSH Enabler

[English](README.md) | **Русский**

Сгенерировано Claude AI на основе данного исследования: https://4pda.to/forum/index.php?showtopic=1115130&view=findpost&p=143819120

Инструменты для **расшифровки, модификации и повторной зашифровки файлов резервных копий
конфигурации (`.bin`)**, создаваемых роутерами Cudy (семейство WR3000 / TR3000 и родственные
модели), чтобы **включить доступ по root SSH (и telnet)** на устройстве после восстановления
изменённой резервной копии.

Поставляется в виде двух интерфейсов с общим ядром:

- **`cli.php`** — инструмент командной строки.
- **`index.php`** — небольшой веб-интерфейс (загрузите резервную копию в браузере и получите
  изменённую обратно).
- **`common.php`** — вся общая логика (криптография, tar на чистом PHP, встроенный overlay и
  загрузчики `.env` / `models.txt`). Оба интерфейса подключают его через `require`.

Всё написано на **чистом PHP** — без пакетов Composer и без внешних библиотек. Работа с tar
реализована с нуля; используются только встроенные расширения PHP `openssl` и `zlib`. Дерево
`etc/` + `overlay/`, включающее SSH, встроено прямо в `common.php`, поэтому дополнительных файлов
с данными не требуется.

> ⚠️ **Используйте только на оборудовании, которым владеете.** Это изменяет резервную копию
> *вашего собственного* роутера, чтобы вернуть к нему административный доступ. Включение
> SSH/telnet и установка пароля root ослабляют безопасность устройства — делайте это осознанно,
> используйте надёжный пароль и не выставляйте управляющие службы роутера в интернет.

## Что именно он делает

Резервная копия настроек Cudy — это **не** обычный архив. Файл `.bin` имеет вид:

```
AES-128-CBC( gzip( tar( файлы конфигурации /etc … ) ) )  + 48-байтовый зашифрованный заголовок
```

- **Шифрование:** AES-128-CBC, нулевой IV, нестандартная поблочная упаковка с маркером конца
  данных (восстановлено реверс-инжинирингом прошивочного `/usr/bin/crypt`).
- **Ключ:** `MD5( "<МОДЕЛЬ>@<KEY_BASE>" )` — то есть ключ зависит от **модели роутера**. Общий
  секрет (`KEY_BASE`) зашит в прошивку; между устройствами меняется только префикс модели.

> 🔑 **Значение `KEY_BASE` нужно задать самостоятельно** через файл `.env` в каталоге проекта,
> рядом с `common.php`, с одной строкой:
>
> ```
> KEY_BASE=настоящий-секрет-прошивки
> ```
>
> Скопируйте `.env.example` в `.env` и заполните. Оба интерфейса читают один и тот же `.env`. Без
> корректного ключа инструмент использует заглушку `xxx`, и ничего не расшифруется. Файл `.env`
> игнорируется git, поэтому секрет никогда не попадёт в репозиторий.
- **Заголовок:** 48-байтовый блок, содержащий magic-значение (`0xA1ECD5BD`), метку времени,
  случайное значение и строку сборки прошивки.

Инструмент:

1. **Автоматически определяет модель**, перебирая ключи известных моделей по очереди, пока
   magic-значение расшифрованного заголовка не совпадёт — так что знать модель заранее не нужно.
2. **Расшифровывает** полезную нагрузку.
3. **Распаковывает gzip и tar** (на чистом PHP).
4. **Добавляет небольшое встроенное дерево `etc/` + `overlay/`**, которое включает SSH/telnet
   при загрузке (см. ниже), заменяя одноимённые записи и оставляя остальную конфигурацию
   нетронутой.
5. **Устанавливает пароль root** по вашему выбору (переменная `NEWPASS` в `etc/rc.local`).
6. **Снова упаковывает в tar, gzip и шифрует** тем же ключом модели, сохраняя исходную строку
   сборки в заголовке.

Результат — готовая к использованию резервная копия, которую вы восстанавливаете через обычную
страницу роутера *«Восстановление конфигурации»*.

### Что внедряется (`etc/rc.local`)

При следующей загрузке изменённый `rc.local`:

- удаляет скрипт `uci-defaults`, который иначе сбросил бы пароль root,
- комментирует проверку `bdinfo dbg` в init-скриптах dropbear/telnet,
- создаёт флаг отладки `/etc/rom_dbg`,
- включает `ttylogin`,
- **устанавливает пароль root** в выбранное вами значение,
- включает и запускает **dropbear (SSH)** и **telnet**.

Точный скрипт встроен в `common.php` (ищите `embedded_entries()`). Строка `NEWPASS='...'`
переписывается вашим паролем при каждом запуске — инструмент всегда спрашивает пароль, даже если
резервная копия уже была изменена ранее.

## Поддерживаемые модели

Модели перечислены в **`models.txt`** (по одной на строку) и перебираются сверху вниз; побеждает
первая, у которой совпадает magic заголовка:

```
AP1300, AP3000, C200P, LT300, LT400, LT500, LT700, M1200, M1300, M1800,
M3000, R700, RE1200, RE1800, RE3000, TR30, TR3000-256MB, WBR3000UAX,
WR1300, WR2100, WR3000, WR3000E, WR3000H, WR3000P, WR3000S,
WR3000U-256MB, X6
```

Оба интерфейса читают один и тот же `models.txt` (рядом с `common.php`). Если ваша резервная копия
от другой модели, использующей ту же схему, просто добавьте её точную строку на отдельной строке.
Определение безопасно: неверный ключ просто не пройдёт проверку magic, и будет испробована
следующая модель.

## Требования

- **PHP 8.0+** (CLI для инструмента командной строки или PHP-FPM/`php -S` для веб-интерфейса)
- Расширения PHP **`openssl`** и **`zlib`** (оба включены в стандартных сборках)

Проверка:

```bash
php -v
php -m | grep -E 'openssl|zlib'
```

## Использование из командной строки (`cli.php`)

```bash
php cli.php <input.bin> [output.bin] [--pass=<sshpass>] [--model=<model>]
```

- `<input.bin>` — зашифрованная резервная копия, выгруженная из роутера.
- `[output.bin]` — необязательно; по умолчанию `<input>-patched.bin`.
- `--pass=<sshpass>` — пароль root/SSH, который нужно установить. Если не указан, будет
  запрошен.
- `--model=<model>` — пропустить автоопределение и принудительно задать ключ модели.

**Пример:**

```bash
php cli.php backup-WR3000U-256MB-2026-07-26.bin --pass='MyStrongPass!'
```

```
[+] Model detected: WR3000U-256MB
    build=2.4.29-20260427-104733  date=2026-07-26 10:02:04  payload=35426 bytes
[+] SSH enabled
[+] Set NEWPASS in etc/rc.local

[✓] Done. Wrote backup-WR3000U-256MB-2026-07-26-patched.bin (36910 bytes), model=WR3000U-256MB
```

## Использование веб-интерфейса (`index.php`)

Интерфейс в браузере, обслуживаемый `index.php` (использует `common.php`).

### Файлы

| Файл | Назначение |
|------|------------|
| `index.php` | Веб-интерфейс: JSON API (`detect` / `patch`), отдаёт `page.html`. |
| `common.php` | Общая логика: криптография / tar / overlay / загрузчики. |
| `page.html` | HTML-представление. |
| `style.css` | Стили (тема в духе терминала/консоли). |
| `script.js` | Логика фронтенда. |
| `models.txt` | Список моделей. |
| `.env` | Ваш `KEY_BASE` (создайте из `.env.example`). |

### Запуск локально

```bash
php -S 127.0.0.1:8080
# откройте http://127.0.0.1:8080/
```

### Развёртывание (nginx + php-fpm или Apache)

Скопируйте файлы проекта в корень веб-сервера, например:

```bash
sudo cp common.php index.php page.html style.css script.js models.txt /var/www/html/
# затем создайте /var/www/html/.env со своим KEY_BASE
```

Убедитесь, что `index.php` входит в список индексных файлов сервера, а `.php` обрабатывается
PHP-FPM.

### Порядок работы

1. **Выберите / перетащите `.bin`.** Браузер загрузит файл, и сервер **автоматически определит
   модель**; определённая модель и информация о сборке отобразятся в консольном логе.
2. Если определение успешно, **появятся поле пароля SSH и кнопка «run»**.
3. Введите пароль и нажмите **run** — резервная копия будет изменена на стороне сервера, а
   пересобранный `.bin` **скачается автоматически**.

> Размер загрузки ограничен параметрами PHP `upload_max_filesize` / `post_max_size` (по
> умолчанию 2 МБ / 8 МБ). Резервные копии крошечные (десятки КБ), так что это не проблема; при
> необходимости увеличьте лимиты.

> 🔒 Веб-интерфейс расшифровывает прошивку и устанавливает пароль root, используя ключ из `.env`.
> **Держите его на localhost или в доверенной локальной сети — не выставляйте в публичный
> интернет** и добавьте аутентификацию, если к нему есть доступ у других.

## Восстановление изменённой резервной копии на роутер

1. Войдите в веб-админку роутера.
2. Перейдите на страницу конфигурации **Резервное копирование / Восстановление**.
3. **Восстановите** из изменённого файла `*-patched.bin`. Роутер перезагрузится.
4. После перезагрузки подключитесь по SSH как `root` с установленным вами паролем:

   ```bash
   ssh root@192.168.10.1
   ```

   (Telnet на порту 23 также включён как резервный вариант.)

Если что-то пойдёт не так, у вас останется **исходная, неизменённая резервная копия** —
сохраните её.

## Структура репозитория

```
.
├── common.php      # общая логика: криптография, tar на чистом PHP, overlay, загрузчики .env/models
├── cli.php         # интерфейс командной строки
├── index.php       # веб-интерфейс (JSON API + отдаёт page.html)
├── page.html       # веб-представление
├── style.css       # веб-стили
├── script.js       # логика веб-фронтенда
├── models.txt      # список поддерживаемых моделей (по одной на строку)
└── .env.example    # шаблон для .env (хранит KEY_BASE)
```

И `cli.php`, и `index.php` — это тонкие интерфейсы, которые делают
`require __DIR__ . '/common.php'`, поэтому вся логика криптографии, tar и overlay находится в
одном месте. `KEY_BASE` и список моделей берутся из `.env` и `models.txt` рядом с `common.php`.

## Как работает определение (для любопытных)

```
для каждой МОДЕЛИ из models.txt:
    key = MD5(МОДЕЛЬ + "@" + KEY_BASE)        # 16-байтовый ключ AES-128
    header = AES-128-CBC-decrypt(первые 48 байт, key, IV=0)
    если little-endian uint32 в header[0] == 0xA1ECD5BD:
        → верная модель найдена
```

Поскольку неверный ключ даёт неверное magic-значение, определение никогда не даёт ложных
срабатываний.
